# 明日方舟寻访公告 API 文档

## 脚本信息

- **文件名**: `ArknightsBanner.py`
- **定时任务**: `0 10 * * *` (每天10:00执行)
- **功能**: 监控明日方舟官网限时寻访（卡池）公告，提取每期卡池数据并在更新时推送通知

## 功能说明

该脚本会：
1. 调用官网公告列表 API，扫描「活动」分类下的公告
2. 三层过滤识别卡池公告（见下文），可抓到"活动附带寻访"等标题无"寻访"的公告
3. 拉取每期卡池公告详情页，解析正文段落
4. 提取卡池结构化数据：寻访类型 / 名称 / 活动时间 / UP干员 / 出率 / 保底规则 / 兑换所
5. 与本地状态文件比对，仅在有**新卡池公告**时推送通知

## 卡池公告识别（三层过滤）

| 层级 | 规则 | 说明 |
|:---|:---|:---|
| ① 标题 | 含"寻访" | 独立寻访公告（如 `[限定寻访·庆典]【承诺】...`） |
| ② 摘要 | 含卡池关键词 | 标题无"寻访"但摘要含"出现率上升/寻访开启/占6★出率..."等（活动附带寻访） |
| ③ 详情 | 正文含卡池数据 | 对仅摘要命中的候选，抓详情确认含"出现率上升/占X★出率"，避免误报 |

> 例：`[活动预告]主题曲第十二章预热...` 标题无"寻访"，但正文含【前路回响】限时寻访 + UP干员 + 出率，会被 ②③ 抓到。

## 扫描策略（增量全量）

- **首次运行**：扫描全部页（约 39 页 / 230 条），记录所有 cid 为已知，仅推送最新一期
- **日常运行**：从第 1 页扫起，遇某页全部 cid 已知即停（新公告必在前几页），仅推送新增卡池

## 官网与接口

### 公告官网

- **公告列表页**: `https://ak.hypergryph.com/news`
- **公告详情页**: `https://ak.hypergryph.com/news/{cid}`

### 列表接口（逆向所得）

**URL:** `GET https://ak.hypergryph.com/api/news?category={category}&page={page}`

**参数:**

| 参数 | 说明 |
|:---|:---|
| `category` | `LATEST`(最新) / `ANNOUNCEMENT`(公告) / `ACTIVITY`(活动) / `NEWS`(新闻) |
| `page` | 页码，从 1 开始，每页 6 条 |

**响应:**

```json
{
  "code": 0,
  "data": {
    "list": [
      {
        "cid": "8588",
        "tab": "1",
        "sticky": false,
        "title": "[狩猎凯旋干员寻访]【砺火成锋】限时寻访即将复刻开启",
        "author": "【明日方舟】运营组",
        "displayTime": 1781254800,
        "cover": "",
        "extraCover": "",
        "brief": "活动时间：06月15日 16:00 - 06月29日 03:59..."
      }
    ],
    "total": 230,
    "end": false
  }
}
```

| 字段 | 说明 |
|:---|:---|
| `cid` | 公告 ID，对应详情页 URL `/news/{cid}` |
| `tab` | 分类：`0`=公告 `1`=活动 `2`=新闻 |
| `title` | 公告标题，`[寻访类型]【寻访名称】` 格式 |
| `displayTime` | 发布时间 Unix 时间戳（秒） |
| `brief` | 摘要（截断） |
| `total` | 该分类公告总数 |
| `end` | 是否末页 |

### 详情接口

**URL:** `GET https://ak.hypergryph.com/news/{cid}`

返回 Next.js SSR HTML，正文为 `<p>` 段落。脚本通过以下规则提取正文：

1. 移除所有 `<script>` 块（含 RSC flight data，避免内容重复）
2. 以日期标记 `\d{4} // \d{2} / \d{2}` 作为正文起点
3. 截断到健康提示页脚「本网络游戏适合...」前
4. 提取所有 `<p>...</p>` 段落纯文本
5. 提取 `data-width="1560"` 的 `<img>` 作为卡池封面

## 卡池数据提取规则

适配两种公告格式：独立寻访（`★★★★★★：麒麟R夜刀（占6★出率的50%）`）与活动附带寻访（`★★★★★★（6★出率：2%）：琴柳 / 号角`）。

| 字段 | 提取规则 |
|:---|:---|
| 寻访类型 | 优先正文 `◆...寻访为【xxx】`，回退标题 `\[xxx\]` 前缀 |
| 寻访名称 | 优先正文 `活动期间【xxx】...寻访开启`，回退标题 `【xxx】` |
| 活动时间 | 定位寻访说明段，取其前面最近的 `活动时间：`（避免多子活动取错） |
| 6★ UP干员 | `^★{6}` 开头且不含"寻访数据契约"的段落 |
| 5★ UP干员 | `^★{5}` 开头且不含"寻访数据契约"的段落 |
| 保底与规则 | `◆` 开头的注意事项 + 含「累计寻访/必定」的保底说明 |
| 兑换所 | 含「寻访数据契约」且为交换所/可兑换干员的段落 |

## 状态文件

### config/.arknights_banner_state.json

```json
{
  "known_cids": ["2825", "7377", "8588"],
  "notified_cids": ["2825", "7377", "8588"],
  "last_run": "2026-07-07 22:10:04"
}
```

- `known_cids`: 已扫描到的所有公告 cid（含非卡池，用于增量停止基线）
- `notified_cids`: 已推送通知的 cid
- 首次运行时扫描全部页并记录所有 cid，仅推送最新一期；后续增量扫描遇已知即停，仅推送新增卡池
